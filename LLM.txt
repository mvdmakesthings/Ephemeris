# Ephemeris: AI Context for Code Understanding

> **Purpose of this file**: Architectural context and design decisions for AI-assisted coding tools. For user-facing documentation, see [README.md](README.md). For contributor conventions, see [CLAUDE.md](CLAUDE.md).

## Project Philosophy

**Dual purpose**: Ephemeris serves Swift developers building satellite tracking apps (including antenna pointing and SDR Doppler correction) and learners studying orbital mechanics. Documentation is theory-first: the math, then the Swift.

**Pure Swift**: No C/C++ code and no dependencies beyond Foundation. Algorithms come from published sources (Vallado, Spacetrack Report #3, Meeus).

**Readable and verified**: Code is written to be read and learned from, with comments that explain the physics. Every algorithm is tested against an independent reference: published worked examples, Vallado's SGP4 verification set, python-sgp4, or Skyfield.

- **Language**: Swift 6 (tools 6.0)
- **Platforms**: iOS 16+, macOS 13+, watchOS 9+, tvOS 16+, visionOS 1+
- **Dependencies**: None
- **Geodetic standard**: WGS-84 (SGP4 uses WGS-72 gravity constants, as TLEs require)

## Architecture

```
Sources/Ephemeris/
├── Coordinates/   CoordinateTransforms, GeodeticPosition, Vector3D
├── Observation/   Observer, Topocentric (+ Propagator.topocentric)
├── Parsing/       TwoLineElement
├── Propagation/   Propagator, StateVector, KeplerianOrbit, SGP4 (+ deep space), GravityModel
├── Time/          Date.julianDate, Date.greenwichMeanSiderealTime
├── Tracking/      GroundTrack, SkyTrack, PassPrediction (+ Propagator extensions)
└── Utilities/     PhysicalConstants, type aliases, angle conversion
```

### Core Types

- **`TwoLineElement`**: Parses and validates NORAD TLEs (2- or 3-line, any line endings, Alpha-5 catalog numbers, checksums). All fields public; epoch is a `Date`.
- **`Propagator`** (protocol): requires only `stateVector(at:)`. Extensions provide `calculatePosition(at:)`, `topocentric(at:for:applyRefraction:)`, `predictPasses(...)`, `groundTrack(...)`, `skyTrack(...)`.
- **`SGP4`**: The propagator for TLE data. A port of Vallado's `sgp4unit.cpp`, including SDP4 deep-space terms. Output frame is TEME.
- **`KeplerianOrbit`**: Two-body propagator for teaching. Can be built from a TLE or from chosen elements.
- **`Observer`**, **`Topocentric`**, **`GeodeticPosition`**, **`PassWindow`**, **`GroundTrackPoint`**, **`SkyTrackPoint`**: immutable, `Sendable`, `Hashable`, `Codable` value types.
- **`CoordinateTransforms`** (caseless enum): geodetic ↔ ECEF, ECI → ECEF (position and state), ECEF → ENU, ENU → azimuth/elevation/range, refraction.

## Design Decisions

### SGP4 for tracking, two-body for teaching
TLEs are mean elements fitted with SGP4, so only SGP4 reproduces the orbit they describe. Two-body motion ignores J2, which turns a low orbit's plane by several degrees per day. The SGP4 port keeps the reference variable names so it can be checked line by line, and matches Vallado's `tcppver.out` to within 0.12 mm.

### One implementation of observer geometry
All observer and tracking features are `Propagator` extensions, so a new propagator gets them by implementing `stateVector(at:)`.

### Value types everywhere
All public types are immutable structs or enums and are `Sendable`, so whole-catalog propagation can use Swift concurrency safely. `SGP4` is stateless: its deep-space integrator restarts from epoch on each call (results are identical to the caching reference).

### Errors
- `TLEParsingError`: malformed text, with field name and value
- `SGP4Error`: decay or invalid elements, with the reference error codes
- `precondition` for programmer errors (for example e ≥ 1 for `KeplerianOrbit`)

## Algorithms

| Algorithm | Location | Method | Reference |
|-----------|----------|--------|-----------|
| TLE → orbit | `SGP4` | SGP4/SDP4 | Vallado et al. 2006, AIAA 2006-6753 |
| Kepler's equation | `KeplerianOrbit.solveKeplersEquation` | Newton-Raphson, 1e-12 rad | Vallado Alg. 2 |
| GMST | `Date.greenwichMeanSiderealTime` | IAU-82 polynomial | Vallado Eq. 3-47 |
| ECEF → geodetic | `CoordinateTransforms.ecefToGeodetic` | Fixed-point iteration | Vallado Alg. 12 |
| Refraction | `CoordinateTransforms.apparentElevation` | Sæmundsson | Meeus Eq. 16.4 |
| Pass events | `Propagator.predictPasses` | Sampling, bisection (0.1 s), golden-section | (none) |

## Testing

XCTest (`swift test`). Test names follow `test[Feature]_[Scenario]_[ExpectedBehavior]` with Given-When-Then comments. Key suites:
- `SGP4VerificationTests`: all 33 satellites / 666 points of Vallado's verification set
- `EndToEndCrossCheckTests`, `PassPredictionTests`: agreement with Skyfield
- `KeplerianOrbitTests`: published examples plus conservation of energy and angular momentum
- `TopocentricTests`: range rate against the numerical derivative of range

## Known Limitations

- SGP4 accuracy is limited by the TLE: about 1 km at epoch, growing 1-3 km/day in LEO
- UT1 − UTC (up to 0.9 s) and polar motion are not applied
- Refraction is an optical model
- Earth-orbiting satellites only

## Guidance for AI Tools

**When changing code:**
- Keep value semantics and `Sendable` conformance
- Do not rename variables inside the SGP4 port or change its operation order; rerun `SGP4VerificationTests`
- Comment the physics and math of each step, with equations and references
- Test against independent references, not just self-consistency
- Keep files under 600 lines and pass `swiftlint lint --strict`

**When explaining concepts:**
- Start with physical intuition, then the equations, then the Swift
- Use real examples (ISS, GPS, geostationary)
